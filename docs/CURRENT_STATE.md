## W5 implemented scope

- **W5-A Business Overview:** the empty `/admin` placeholder is replaced by an owner-only, database-backed dashboard. Periods are last 7/30/90 Africa/Cairo calendar dates including today (`[Cairo start, next Cairo midnight)`). Metrics: accepted requests in the period; current all-time `new` backlog; period-cohort contacted/closed; UTM-tagged rows as a separate acquisition hint; source breakdown; historical plan interest; historical promotion context (active/no-active/legacy-unknown/invalid-unknown/no-plan); daily accepted counts; latest five all-time requests linking to protected detail. No revenue/ARR/MRR/subscription metric and no full-table browser load. Unavailable/not-configured/unauthenticated storage states are never shown as zero. Source/UTM is a bounded attribution hint, not proof of navigation.
- **W5-B GA4 analytics:** server-only Google Analytics 4 Data API adapter with read-only `analytics.readonly` service-account credentials. At most one token request plus four traffic reports per dashboard load, plus one optional event-specific key-event-rate report only when join-success events exist; 5s timeouts, 5-minute server cache keyed by property/account/API base/date range/schema version, zod-validated responses, honest disabled/not-configured/unavailable/partial states, and provider failure isolation from business KPIs. The generic `sessionConversionRate` is not used as join conversion; `sessionKeyEventRate:join_request_success` is shown only when GA4 has the event registered, otherwise the rate is explicitly unavailable. Tracking is disabled by default and consent-gated; no script/cookie/event before consent. The public footer provides reversible analytics preferences; withdrawal applies Consent Mode denial, sets `ga-disable`, expires accessible `_ga`/`_ga_*`/`_gid` cookies, stops app events immediately and persists denial across reloads (with an explicit reload option to unload a loaded tag). Only the seven public routes; sanitized `page_location`/`page_referrer` plus tag-level defaults; no query strings/PII; no admin/login/preview/request/API tracking, with cleanup disabling measurement when the public layout unmounts. Event vocabulary: `page_view`, `join_cta_click`, `join_request_success` (success only after completed intake, token-deduplicated). GA Ads/remarketing/Signals/ad personalization and session replay are disabled; external enhanced-measurement/history-pageview settings must be disabled and verified. Cross-source request/user ratio is labelled a ratio, not a verified visitor conversion. External activation is required; CI uses stubs and never calls Google.
- **W5-C Telegram notifications:** optional, separate website bot to one fixed private owner destination. Request is persisted/committed before bounded post-commit delivery; failure never rolls back the request. Durable states `skipped | pending | sending | sent | failed | uncertain`; the owner can test the saved destination while automatic delivery is disabled, and testing never enables it. A DB claim records a stable attempt timestamp; completion is fenced on the exact claim and `sending` state so an older attempt cannot overwrite a newer claim/result. A provider success whose result cannot be persisted is reported as `uncertain` (`persistence`), not failure. 5-minute stale recovery; owner-only explicit retry; sent notifications are never auto-resent; uncertain retry may duplicate and is warned. Plain-text message contains status, plan, bounded source, historical promotion context, Cairo time and a protected link built from validated `BETTER_AUTH_URL`; no name/phone/email/business/notes/tokens. `TELEGRAM_BOT_TOKEN` stays server-side; private chat ID is stored only in private settings; mutation readbacks return only the masked destination; changing destination clears cached verification; no public pairing/getUpdates/commerce-bot access. No exactly-once claim.
- **W5-D Settings:** one typed `site_settings` row with public contact/social columns and private integration columns; no generic key/value editor. Public loader projects only approved fields and re-validates stored values. Strict URL/provider validation rejects unsafe schemes, credentials, custom ports, queries, fragments and arbitrary hosts. Contact page/footer consume the projection; missing values are honest empty states. Owner-authorized server actions validate server-side, use independent optimistic revisions per group and atomic row-locked updates, reject stale writes and report success only after commit. Notification mutation responses expose only the masked destination; the protected owner edit page may hold the full destination for intentional editing, but public loaders/pages never receive it. Public changes are immediate; CMS keeps its draft/published workflow. Owner account information is read-only in Settings; `OWNER_EMAIL`, passwords and sessions are not editable there. No global CTA setting is added because CMS/code-controlled CTA ownership already exists.
- **NKW-W41-001 corrected:** the plan editor no longer forces a disabled promotion to `enabled: true`. Disabled shows ordinary current prices and an explicit disabled note; enabled future promotions are labelled hypothetical simulations; active/expired states are truthful. Server effective-offer semantics, published pricing and historical snapshots are unchanged. NKW-W41-002 (native date/time control) remains deferred to physical Android evaluation in W6; no custom picker was added.
